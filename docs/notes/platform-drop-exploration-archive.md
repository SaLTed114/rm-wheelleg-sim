# 实体平台跌落实验归档

> 本文归档 2026-08-11 至 2026-08-13 的实体平台驶离探索。它保存已经完成的实验问题、失败归因和精简依据，不定义当前生产控制器的验收标准。对应历史主要位于提交 `f63bec9`（平台跌落实验）、`fa89fff`（主动落地悬挂探索）和 `0bd19ba`（ACTIVE 正式接管）。

## 为什么曾经需要这组实验

最初只有“将机器人抬起后释放”的跌落实验。它能隔离观察空中腿角和支持力识别，却不能回答机器人实际驶出直角平台时会不会因底盘净空、前后方向或轮子离台不同步而先撞到边缘。因此加入了出生在实体平台、完成起立和加速、再自动驶离 `200/400 mm` 高台的场景。

平台探索最初没有生产落地状态机。MuJoCo 接触真值负责切换空中和触地后的 benchmark 策略，实验目标是依次弄清三个问题：直角边缘是否能通过；空中快速伸腿是否能减少机体下落；只控腿长与保留腿角 LQR 有什么区别。后续又用相同框架探索了触地轴向阻抗、移动平衡点和无扰退出，最终才将得到的语义迁入纯 C ACTIVE support phase。

## 已归档的 36 个平台机理案例

### 净空与离台速度矩阵：24 例

第一组是 `高度 {200,400 mm} x 工作腿长 {0.18,0.24 m} x 速度 {0.5,1.0,2.0 m/s} x 空中策略 {length_only,leg_lqr}`。它的主要价值不是挑选空中控制器，而是暴露直角平台的几何限制。

`0.18 m` 腿长以 `0.5/1.0 m/s` 驶离时，底盘或后腿会在形成干净腾空前持续碰撞平台边缘；`200 mm、2.0 m/s` 虽能恢复，旧的固定腿长案例仍记录到机体与平台接触。`0.24 m` 提高了净空，`200 mm` 六例均能恢复，但低速仍有边缘接触；`400 mm、0.5/1.0 m/s` 仍会碰边并发生严重姿态恶化。只有 `0.24 m、2.0 m/s` 在两个高度上形成了较干净的驶离和恢复。

这组矩阵确立了两个边界。第一，低速失败不能归因于 LQR，因为碰撞先于空中姿态恶化发生，而且 `length_only` 与 `leg_lqr` 同样受到几何约束。第二，测试台阶时不能只指定高度，还必须指定工作腿长、驶离方向和实际边缘速度；“慢一点更安全”对直角平台并不成立。

这 24 例不再常驻的原因是：它们已经回答了净空问题，其中多数案例被已知边缘碰撞污染；它们使用 benchmark 真值切换，不能代表当前生产 ACTIVE 落地路径；继续让 CTest 逐次重放只能证明场景运行结束，不能提供新的控制结论。几何或碰撞模型以后若发生实质变化，应按问题重新设计小型净空实验，而不是原样恢复整张矩阵。

### 快速伸腿与速度扫描：8 例

第二组在 `200 mm、0.18 m` 下比较不伸腿的 `1.5/2.5 m/s`，以及离台后从 `0.18 m` 快速伸至 `0.38 m` 的 `1.5/2.0/2.5 m/s x {length_only,leg_lqr}`。

不伸腿时，机体在首次触地前下降约 `171-178 mm`。快速伸腿后下降量缩小到约 `19-24 mm`，触地时实际腿长约 `0.31-0.35 m`，空中关节峰值请求约 `30-31 N*m`，没有触发 `40 N*m` 软件限幅。这证明伸腿不是为了在空中移动整机高度，而是尽早建立轮地接触，并给触地后的主动压缩留下行程。

`1.5 m/s` 仍会碰平台边缘，因此不适合作为干净机理门禁。`2.0` 与 `2.5 m/s` 的结论重复，其中 `2.0 m/s` 更接近稳定工况且已有完整历史对照，所以只保留该速度下的两例：

```text
platform_drop_200mm_l0p18_v2p0_length_only_air_extend_l0p38
platform_drop_200mm_l0p18_v2p0_leg_lqr_air_extend_l0p38
```

在这组单变量对照中，两例均恢复且没有非轮接触。`length_only` 的触地左右腿角差约为 `1.65 deg`，`leg_lqr` 约为 `0.39 deg`；后者两侧空中最大腿角误差也更小。与此同时，`leg_lqr` 的触地机体 pitch 约为 `1.21 deg`，高于 `length_only` 的约 `0.31 deg`。这不是矛盾：特殊 LQR 的目标是让虚拟腿相对世界接近竖直，它会与机体交换角动量，并不直接最小化机体 pitch。

### 平台离台 pitch-rate 扰动：4 例

第三组在保留 `0.18 -> 0.38 m` 快速伸腿的同时，于离台瞬间人工注入 `-0.5/+0.5 rad/s` pitch rate，并分别运行 `length_only` 和 `leg_lqr`。四例均恢复且没有非轮接触；LQR 在两个扰动方向都减小了空中腿角误差和触地左右腿角差。

这些结论仍然有效，但案例不再常驻。手动抬升释放已经以更干净的方式覆盖 `pitch rate {-0.5,0,+0.5 rad/s} x {length_only,leg_lqr}`：它没有平台边缘碰撞这一混杂变量，还同时验证轮子离地距离和支持力 AIR/GROUND 检测延迟。相同假设不需要在两个场景中永久维护。

## 触地悬挂探索的阶段性结论

快速伸腿解决的是“尽早接地”，没有解决“如何承接冲击”。早期 benchmark 因此在 `200 mm、约 2.0 m/s、0.18 -> 0.38 m、leg_lqr` 上用 MuJoCo 单轮接触真值比较位置强撑和五组逐腿轴向阻抗。最初的 `180 N` 力上限使所有候选被共同限幅，约 `267.2 N` 的 MuJoCo 法向力峰值又发生在触地首采样，不能拿来选择 K/D。Jacobian 复核表明 `40 N*m` 软件关节限幅在 `0.18-0.38 m` 纯轴向输出时至少对应约 `263 N/leg`，因此探索上限放宽到 `240 N`。

在 `240 N` 下，`K={400,800,1200},D=80` 的最大腿压缩约为 `83/76/73 mm`，`K=800,D={40,120}` 约为 `84/73 mm`。差异仅约 `10 mm`，且多数候选仍受到力上限影响，所以不能仅凭 GUI 或单一稳定时间宣布最优参数。最终选择 `K=800 N/m,D=80 N*s/m` 是首版折中，不是全局最优证明。

固定触地平衡点会长期顶住长腿，与落地后快速收腿的动作相反。探索策略随后改为每腿首次触地捕获 `L_eq=L_touch`，再以 `0.8 m/s` 将平衡点移回工作腿长；待双腿接触、平衡点到位、腿速和机体竖直速度均低于 `0.1 m/s` 并保持 `50 ms` 后，按当前轴向力反算位置 PD 等效参考，再以 `0.1 m/s` 回归普通支撑。五组候选均完成退出，切换首采样支持力变化小于 `1 N`，没有二次冲击。

上述托管控制器、五组 K/D 注册案例和真值驱动回收逻辑在生产接管完成后已经删除。它们只应作为设计来源保存在本文和 Git 历史中，不应重新进入 benchmark，除非未来明确要重新研究触地控制律，并为新假设设计独立实验。

## 生产 ACTIVE 接管

生产 support phase 使用支持力和 IMU 融合识别 `GROUND -> AIRBORNE -> LANDING_RETRACT -> GROUND_RECOVER -> GROUND`。AIRBORNE 关闭轮输出、将腿伸至 `0.38 m` 并只保留腿角 LQR；LANDING_RETRACT 恢复轮和完整姿态 LQR，逐腿使用 `K=800 N/m,D=80 N*s/m`、`0-240 N`、`3000 N/s` 的轴向力限制和 `0.8 m/s` 移动平衡点；GROUND_RECOVER 无扰切回位置支撑。纵向和偏航参考在全过程继续推进。

当前保留四个生产案例：正向 `200 mm / 2.0 m/s`、正向 `400 mm / 2.5 m/s`、反向 `200 mm / 2.0 m/s` 和反向 `400 mm / 2.5 m/s`。它们从起立到落地恢复始终调用普通控制入口，不使用 MuJoCo 接触真值改写控制命令。`200 mm` 代表稳定工况，`400 mm` 代表压力工况；正反方向必须分开，因为底盘几何、pitch 响应和左右轮离台顺序并不对称。

400 mm 正向历史结果的实际边缘速度约为 `2.40 m/s`，飞行约 `186 ms`，触地 pitch 约 `4.44 deg`，落地后最大 pitch 约 `4.67 deg`，最大 roll 约 `9.66 deg`，左右轮触地相差约 `27 ms`。离台时间本身也相差约 `27 ms`，说明主要非对称在平台出口已经形成，而不是落地控制凭空制造。400 mm 反向实际边缘速度约为 `-2.55 m/s`，触地 pitch 约 `1.68 deg`，最大 roll 约 `8.95 deg`，左右轮触地相差约 `22 ms`。这些理想仿真结果没有出现发散、反弹、非轮接触或关节饱和，但不能外推为实车上限。

## 精简后的常驻边界

跌落相关常驻案例由 46 个缩减为 12 个：6 个手动抬升释放案例用于隔离空中腿角和支持力检测；2 个平台机理案例用于比较快速伸腿下是否保留腿角 LQR；4 个生产 ACTIVE 案例用于覆盖正反方向和 `200/400 mm` 落差。项目全部常驻 case 因此由 51 个降为 17 个。

平台机理自动测试不再以“场景跑完”为唯一条件。两例必须完成、恢复、保持有限、无姿态发散且无非轮接触；此外 `leg_lqr` 必须同时降低两侧空中最大腿角误差和触地左右腿角差。生产 ACTIVE 的验收仍单独进行，不能用机理案例代替。

## 使用这些结论时的限制

平台是理想刚性直角边缘，机体复杂 mesh 直接参与碰撞；MuJoCo 执行器只有力矩限幅，没有电机速度、功率、热和电池模型。平台出生阶段的轻微 yaw 偏转会造成左右轮非同时离台，结果对初始姿态和接触细节敏感。支持力阈值、K/D 和力限幅尚未经过实车噪声、结构柔性、轮胎形变或地面不平整验证。

因此本文中的失败案例用于说明“为什么当时改变方向”，成功案例用于说明“该机制在当前理想模型中可行”。它们都不是实车安全承诺。未来重新打开这一方向时，应从当前生产 ACTIVE 四例出发，先明确新问题和可观测指标，再增加最少量的单变量案例。
